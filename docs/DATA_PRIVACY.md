# Production Data Privacy, PII Protection & Data Minimization Policy

This document outlines the data privacy architecture, PII classification, masking rules, data minimization standards, and security controls for customer information across the CCATI platform.

---

## 1. PII Field Classification & Inventory

| Field Name | Category | Sensitivity | Masking Strategy | Primary API Endpoints |
|---|---|---|---|---|
| `name` | Direct PII | High | Masked (`mask_name()`) by default | `/customers` (masked), `/customers/{id}` (gated reveal), `/segments/{id}/customers` (masked) |
| `phone` | Direct PII | High | Masked (`mask_phone()`) by default | `/customers` (masked), `/customers/{id}` (gated reveal), `/export/customers` (masked) |
| `email` | Direct PII | High | Masked (`mask_email()`) by default | `/customers/{id}` (gated reveal) |
| `customer_id` | Business Identifier | Low | None (Safe synthetic business ID `CUST-XXXX`) | All customer and prediction endpoints |
| `payment_method` | Sensitive Business Data | Medium | None (Categorical, no bank/card numbers stored) | `/customers/{id}` |
| `monthly_charges` | Sensitive Business Data | Medium | None (Required for CLV & revenue-at-risk) | `/customers`, `/customers/{id}`, `/analytics/*` |
| `total_charges` | Sensitive Business Data | Medium | None (Required for CLV) | `/customers/{id}` |
| `clv` | Business Metric | Low | Derived lifetime value calculation | `/customers/{id}`, `/segments` |
| `contract_type` | Model Feature | Low | None (Categorical) | `/customers`, `/segments`, `/predict` |
| `tenure_months` | Model Feature | Low | None (Integer) | `/customers`, `/segments`, `/predict` |
| `churn_probability`| Operational ML Output | Low | None (Float 0.0 - 1.0) | `/predict`, `/predictions/history`, `/customers` |
| `risk_tier` | Operational Risk Output| Low | None (Low / Medium / High / Critical) | All analytics and customer dashboards |
| `password_hash` | System Secret | Critical | **NEVER EXPOSED** in any API response or log | DB authentication table only |

## 2. PII Masking Utilities
Centralized utility functions located in `backend/app/core/security.py`:
- `mask_name("Jane Doe")` → `"J*** D***"`
- `mask_phone("+1-555-123-4567")` → `"******4567"`
- `mask_email("subscriber@domain.com")` → `"s***@domain.com"`

---

## 3. Data Minimization & Role-Gated Unmasking
- **Default Redaction**: All customer listing endpoints (`/api/v1/customers`, `/api/v1/segments/{id}/customers`, `/api/v1/export/customers`) return masked PII by default.
- **Role-Gated Reveal**: Accessing unmasked customer PII (`GET /api/v1/customers/{id}?reveal_pii=true`) is strictly restricted to `RetentionManager` and `Admin` roles.
- **Audit Logging**: Every PII unmasking event is logged to the `audit_logs` database with actor identity, timestamp, and request correlation ID.

---

## 4. ML Feature Isolation & Model Privacy
- **Pipeline Data Minimization**: Direct PII columns (`name`, `phone`, `email`, `customer_id`) are explicitly excluded from model training feature matrices in `ml_engine/pipelines/training.py`.
- **Explainability Privacy**: SHAP attributions and feature contributions refer exclusively to the individual customer's operational metrics and never expose training population records or neighboring customer profiles.

---

## 5. Export Security
- **Authentication & RBAC**: CSV exports (`/api/v1/export/customers`) require authentication with `RetentionManager` or `Admin` roles.
- **Export Redaction**: Exports generated by non-Admin roles automatically apply `mask_name` and `mask_phone` transformations to protect customer privacy in bulk downloads.

---

## 6. Secure Logging & Audit Policies
- **Zero-Secret Logging**: Passwords, password hashes, JWT tokens, refresh tokens, and raw authorization headers are never logged.
- **Structured JSON Logs**: Production logs emit structured JSON objects with correlation IDs, method, status codes, and non-sensitive metadata.
- **Audit Retention**: Configurable retention window (`AUDIT_RETENTION_DAYS`, default 90 days) with automated and role-gated purge routines.
